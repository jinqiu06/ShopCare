## 真实模型观察

使用已配置的百炼 qwen-plus。用户新授权上限为 8 次对话 / 4 次向量；实际仅 4 / 0，无重试，剩余额度不继续使用。
初始“复制现有库”的执行被自动审批拒绝，理由是已有订单/政策数据的外发适用性未确认；该次未执行、未消耗请求。
调整后仅在全新临时库创建两个模拟用户，不读取现有业务数据或订单/政策；临时 Checkpoint 随测试清理。

固定问题：“我的耳机左边没声音，订单号暂时找不到。请告诉我接下来应提供哪些信息。”

| 场景 | 对话请求 | 请求中的最新偏好 | 正文字符数 |
| --- | ---: | --- | ---: |
| 保存简短后另开会话 | 1 | 回答简短 | 41 |
| 更新详细后另开会话 | 1 | 回答详细 | 184 |
| 原会话删除偏好后询问 | 1 | 未保存，默认长度 | 101 |
| 另一个用户询问 | 1 | 未保存，默认长度 | 107 |

保存、更新和删除三轮各 0 请求。四个真实回答均为 needs_clarification，空政策引用；逐条检查实际发送的系统消息与历史：偏好来源正确、没有旧记忆命令。篇幅变化是一次固定小样本观察，不保证所有问题都满足某个字数阈值。原始消息和响应保存在 Git 忽略的 `data/private/eval/memory-2026-11-17.json`，不含请求头或密钥。

真实内容审查仍发现模型猜测“item 开头”等未提供的编号格式，详细回答还自行举例 O004。没有政策/订单证据支持这些格式说明；本轮不认定为全内容语义通过，未用正则堆砌拦截，也未扩大本轮为全套效果调优。后续交付验收需复查这项已知内容问题。

## 边界和后续

32000 是消息对象序列化字符预算，包含工具参数，不是 token 上限或完整 HTTP 请求大小。工具 schema 不计入。当前轮不会截断；超过预算时 API 返回 413，轮次进入 failed，需新建会话。最多保留两轮旧历史，窗口外订单或故障细节需用户重述；尚无自动摘要和长期事实抽取。

长期偏好仅回答简短/详细，由精确显式命令保存。删除移除生效偏好并排除旧命令轮，归档原消息仍保留。偏好只影响篇幅，不降低用户隔离、政策证据或售后操作限制。业务库与 Checkpoint 分开提交，尚无跨库原子性；写 Checkpoint 失败后，偏好可能已变更，会话标记 failed。
